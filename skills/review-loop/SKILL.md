# review-loop — 기계 검증과 리뷰 반복

구현은 메인 에이전트가 하고, 판정은 코드를 쓰지 않은 리뷰어가 한다. 기계가 잡을 수 있는 건 기계가 먼저 잡고, 리뷰어는 기계가 못 잡는 것(의도·설계·타입 모델링)만 본다.

```
[1 기계 검증] → [2 리뷰] → [3 판정] → [4 수정] → [5 기계 검증] ─┐
                   ↑                                            │
                   └──────────── 반영한 지적이 있으면 ───────────┘
```

**종료 조건: 기계 검증 통과 + 차단 지적 0.** 최대 3라운드.

## 시작 전

- **의도 근거**를 정한다.
  - 신규 기능: 명세 파일. 로직 게이트(G1…) 다이어그램이 없으면 리뷰로 넘어가지 말고 명세부터 채운다(`workflow.md` 명세 작성 단계).
  - 수정(버그): 바뀐 게이트가 있으면 해당 기능 명세의 게이트를 먼저 갱신한다. 없으면 버그 설명과 재현 테스트가 의도 근거다.
- **diff 범위**를 정한다. 보통 작업 시작 커밋(또는 base 브랜치) 대비 + 작업 트리.

## 1. 기계 검증

명령은 매번 프로젝트에서 찾는다. 하네스가 규칙을 정하지 않고, 프로젝트가 정의한 검사를 실행만 한다.

1. git 최상위 `.claude/code-rules.md` 에 검증 명령이 적혀 있으면 그대로 쓴다.
2. 없으면 탐지한다.
   - 패키지 매니저: `pnpm-lock.yaml` → pnpm, `yarn.lock` → yarn, `bun.lock`/`bun.lockb` → bun, `package-lock.json` → npm.
   - 바뀐 파일이 속한 패키지의 `package.json` scripts 에서 찾는다(모노레포면 그 워크스페이스 기준).
     - typecheck: `typecheck`·`type-check`·`tsc`·`check-types`. 없고 `tsconfig.json` 이 있으면 `tsc --noEmit`.
     - lint: `lint`. 자동 수정 스크립트(`lint:fix` 등)는 쓰지 않는다.
     - test: `test`. watch 모드로 뜨면 한 번만 도는 옵션을 붙인다(vitest `run`, jest `--watchAll=false`).
   - 해당 스크립트가 없으면 그 검사는 "없음"으로 기록하고 넘어간다. 지어내지 않는다.
3. **typecheck → lint → test** 순서로 실행한다.
4. 실패하면 고치고 다시 1부터. 통과할 때까지 2로 넘어가지 않는다. 내 변경과 무관한 실패라고 판단되면 그 근거(main 에서도 실패 등)를 확인해 보고에 적고 사용자에게 알린다.
5. 실행한 명령과 결과 한 줄 요약을 남겨 둔다.

## 2. 리뷰

`code-reviewer` 서브에이전트를 **매 라운드 새로** 띄운다(이어 쓰지 않는다 — 지난 라운드의 맥락이 판단을 흐린다). 넘기는 건 포인터뿐이다.

```
의도 근거: <명세 경로 | 버그 설명 + 재현 테스트 경로>
diff 범위: <기준 커밋>..작업 트리
기계 검증: 통과 — <실행한 명령들>
이전 라운드: <없음 | 지적 번호별 처리 결과(반영 / 사용자 판단 / 기각: 이유)>
```

## 3. 판정

리뷰어의 지적을 그대로 받아쓰지 않는다. 메인이 지적마다 하나로 분류한다.

| 분류 | 기준 |
|---|---|
| 반영 | 실행 경로가 증명된 실제 문제 |
| 사용자 판단 | 설계·제품 판단이 걸린 문제. AskUserQuestion 으로 묻는다(질문 방식 규칙을 따른다) |
| 기각 | 호출처가 그 입력을 넘길 수 없는 가정, 취향 차이, 맥락을 모른 지적. 이유를 한 줄로 남긴다 |

여러 라운드에 걸쳐 같은 지적이 기각 이유를 반박하는 새 근거와 함께 돌아오면 다시 판단한다.

## 4. 수정

반영 항목을 고친다. 동작이 바뀌는 수정이면 `tdd` 로 실패 테스트부터 쓴다. 게이트가 바뀌면 명세의 게이트도 같이 고친다.

## 5. 기계 검증 다시

1번과 같은 명령을 다시 돌린다. 실패하면 고치고 다시.

## 6. 반복 또는 종료

- 이번 라운드에 반영한 지적이 있으면 2로 돌아간다.
- 차단 지적이 0이고 기계 검증이 통과면 끝낸다. 권장·참고는 반영하지 않았어도 종료를 막지 않는다.
- 3라운드를 넘기면 멈추고 남은 지적을 그대로 보고한다. 같은 종류의 지적이 라운드마다 반복되면 수정이 아니라 설계 문제일 수 있다고 함께 적는다.

## 보고

마지막 응답에 붙인다.

```
기계 검증: typecheck <명령> 통과 / lint <명령> 통과 / test <명령> 통과 (또는 없음·실패)
리뷰: <N>라운드
- 1라운드: 차단 a / 권장 b / 참고 c → 반영 x, 사용자 판단 y, 기각 z
- 기각: #n <이유>
남은 항목: <없음 | 목록>
```

실행하지 않은 검증을 통과라고 쓰지 않는다.
