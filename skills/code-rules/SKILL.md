# 코드 룰북

기계가 못 잡는 것만 적는다. 타입 에러·lint 위반·테스트 실패는 기계 검증 몫이라 여기 없다.

규칙 ID 는 리뷰에서 인용하는 고정 번호다. 규칙을 지워도 번호는 다시 쓰지 않는다.

## 프로젝트 보강

git 최상위에 `.claude/code-rules.md` 가 있으면 함께 적용한다.

- 프로젝트 규칙 ID 는 `P1`, `P2` … 로 쓴다.
- 프로젝트 파일이 공통 규칙을 바꾸려면 그 ID 를 적는다(`R4 대체: …`, `R4 해제: <이유>`). 적힌 쪽이 이긴다.
- 프로젝트 파일에 검증 명령(typecheck·lint·test)이 적혀 있으면 `review-loop` 가 자동 탐지 대신 그 명령을 쓴다.

## 의도 — 명세 로직 게이트

- **R1. 게이트 대응.** 명세의 로직 게이트(G1, G2 …)마다 그 분기를 구현한 코드와, 그 분기를 검사하는 테스트가 하나 이상 있다. 게이트에 없는 분기가 코드에 있거나, 코드에 없는 게이트가 명세에 있으면 위반이다.
- **R2. 명세 밖 동작.** 명세에 없는 동작(옵션·모드·폴백)을 추가하지 않는다. 필요했다면 명세부터 고친다.

## 범위

- **R3. 최소 diff.** 문제를 푸는 가장 작은 변경. 요청 밖 리팩터·정리를 섞지 않는다.
- **R4. 삭제 우선.** 고치거나 늘리기 전에 지울 수 있는 것(죽은 코드, 쓰이지 않는 import·파라미터, 중복 검증)을 먼저 지운다.
- **R5. 미래용 코드 금지.** 아직 없는 경우를 위한 파라미터·설정·분기·확장 지점을 만들지 않는다.
- **R6. 얕은 추상화 금지.** 호출처가 하나뿐인 래퍼, 인자를 그대로 넘기는 pass-through, 감추는 게 없는 인터페이스를 만들지 않는다. 중복 세 줄이 성급한 추상화보다 낫다.
- **R7. 파일 크기.** 1,000줄 미만이던 파일을 1,000줄 넘게 만들지 않는다. 넘으면 먼저 나눈다.

## 구조

- **R8. 즉석 분기 금지.** 기존 흐름 중간에 특수 케이스용 `if` 를 끼워 넣지 않는다. 상태 머신·테이블·전용 모듈로 옮긴다.
- **R9. 기능 체크를 흩뿌리지 않는다.** 같은 기능 플래그·조건 검사가 공용 코드 여러 곳에 퍼지면 위반이다. 한 곳에서 결정하고 결과를 넘긴다.
- **R10. 한 가지 방법.** 같은 일을 하는 두 번째 방법을 만들지 않는다. 새 API 를 만들면 호출처를 옮기고 옛 경로를 같은 변경에서 지운다.
- **R11. 있는 걸 쓴다.** 이미 있는 헬퍼·유틸·컴포넌트를 다시 구현하지 않는다. 로직은 그것이 속한 레이어·모듈에 둔다.
- **R12. 상태 소유자는 하나.** 같은 상태를 여러 모듈이 쓰거나 각자 사본을 들고 있지 않는다.
- **R13. 손으로 맞추는 목록 금지.** 같은 항목을 두 곳 이상에 나열하지 않는다. 하나에서 파생한다.
- **R14. 호출 깊이.** 질문 하나에 답하려고 3개 넘는 파일·레이어를 따라가야 하면 평평하게 만든다.

## 근본 원인

- **R15. 증상 가드 금지.** 크래시를 null 체크·기본값·try/catch 로 덮지 않는다. 왜 그 값이 들어오는지 고친다.
- **R16. 재시도·폴백으로 계약 위반을 숨기지 않는다.** 실패를 조용히 다른 경로로 돌리지 않는다.

## 경계와 에러

- **R17. 경계에서 한 번.** 외부 입력(네트워크·파일·환경 변수·사용자 입력)은 들어오는 곳에서 한 번 검증하고, 안쪽에서는 다시 검증하지 않는다.
- **R18. 에러를 삼키지 않는다.** 빈 catch, 로그만 찍고 계속 가는 catch 금지. 처리하거나 위로 올린다.
- **R19. 부분 적용 금지.** 함께 바뀌어야 하는 상태가 중간에 실패해 반만 바뀐 채로 남을 수 있으면 위반이다.

## 테스트

- **R20. 동작을 검사한다.** 테스트는 `tdd` 스킬의 `writing-good-tests.md` 를 따른다. 테스트가 가져온 함수가 전부 `undefined` 를 반환해도 통과한다면, 그 테스트는 아무것도 검사하지 않는다.

## 주석

- **R21. why 만.** 코드가 보여 줄 수 없는 이유만 남긴다. 무엇을 하는지 설명하는 주석, 단계 내레이션, 주석 처리된 코드는 지운다.
- **R22. 놀라운 동작은 구조로.** 우리 코드의 이상한 동작을 주석으로 변명하지 않는다. 이름·타입·구조를 바꿔 드러낸다. 외부 라이브러리·플랫폼 제약 설명은 예외.

## 보안

- **R23. 위험한 sink.** 사용자 입력이 검증 없이 SQL·shell·`eval`·`innerHTML`·`dangerouslySetInnerHTML` 로 흘러가지 않는다. 비밀값을 코드·로그·에러 메시지에 남기지 않는다.
