# update-docs — 코드 수정 후 문서 맞추기

코드가 바뀌면 그 코드를 설명하는 문서도 같은 작업 안에서 맞춘다. 플러그인 Stop 훅(`hooks/update-docs-gate.mjs`)이 수정 파일 목록과 함께 이 스킬을 부른다.

## 절차

1. **대응표 읽기** — 레포 루트의 `.claude/docs-map.md`. 없으면 옛 방식인 `.claude/skills/update-docs/SKILL.md` 의 대응표를 본다.
2. **대상 파악** — 훅이 준 목록(없으면 `git diff --name-only` + `git status --short`)을 대응표로 문서에 묶는다.
3. **판단** — 문서마다 "고칠 것 있음 / 없음"을 정한다(아래 기준).
4. **갱신** — 해당 문서만 고친다. 명세 본문엔 파일 경로를 쓰지 않는다(경로는 파일 지도 표가 유일한 출처).
5. **대조 검토(조건부)** — 아래 「서브에이전트 대조」 조건에 걸리면 실행하고, 지적을 반영한다.
6. **보고** — 마지막에 한 줄: `문서 점검: 갱신 <파일들> / 불필요 <이유>`.

대응표에 없는 코드가 바뀌었는데 설명할 문서가 필요해 보이면, 대응표에 줄을 추가하자고 사용자에게 제안한다.

## 고칠지 판단 기준

- **고친다**: 동작·화면·API 계약·데이터 원천이 바뀜 / 파일이 생기거나 옮겨지거나 지워짐(파일 지도 표의 경로) / 새 함정·결정이 생김 / 문서에 적힌 내용이 이제 틀림.
- **안 고친다**: 이름·스타일만 바뀐 리팩터, 문서에 적히지 않는 수준의 내부 구현, 이미 문서가 맞음.
- 판단이 애매하면 "문서가 지금 거짓말을 하는가"로 본다. 거짓이면 고친다.

## 서브에이전트 대조

같은 에이전트가 쓴 코드와 문서를 스스로 보면 놓치기 쉽다. 아래 중 하나면 서브에이전트(general-purpose, 읽기 전용 지시)에 대조를 맡긴다.

- 신규 기능 개발의 마무리
- 한 작업에서 명세 항목을 3개 이상 고쳤거나, 명세를 새로 만든 경우

지시 내용: "명세 `<파일>` 의 각 항목이 `<관련 파일들>` 구현과 맞는지 대조하라. 틀린 항목·구현엔 있는데 명세에 없는 동작·명세 표의 없는/틀린 경로만 목록으로 돌려 달라. 파일은 고치지 마라." 단순 버그 수정·소규모 변경엔 쓰지 않는다(5번 단계 생략).

## docs-map.md 형식

프로젝트마다 한 파일. 표 하나면 충분하다.

```markdown
# 코드 → 문서 대응표

| 바뀐 코드 | 고칠 문서 |
|---|---|
| `src/features/<모듈>/**` | `.claude/skills/<모듈>/SKILL.md`(파일 지도) + 같은 폴더 `features/*.md`(명세) |
| 모듈 폴더 신설·이동·삭제 | `CLAUDE.md` 프로젝트 구조 트리 |
```

이 파일(또는 옛 `.claude/skills/update-docs/SKILL.md`)이 있는 레포에서만 문서 점검 훅이 동작한다.

## 훅이 세는 것

- Edit·Write·MultiEdit·NotebookEdit 로 고친 파일만 센다. Bash 로 고친 파일은 보이지 않는다.
- 문서(`.md`·`.mdx`·`.txt`·`.rst`), 테스트(`*.test.*`·`*.spec.*`·`__tests__/`·`test/`·`tests/`·`src/test/`), `.claude/`·`docs/`·`trash/`·`node_modules/` 아래는 세지 않는다.
- 한 번 막으면 목록을 비운다. 이 점검 라운드에서 새로 고친 코드는 다시 막지 않으니, 점검 중 코드를 고쳤다면 스스로 문서를 한 번 더 본다.
