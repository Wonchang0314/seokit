# Explain Diff Notion

지정된 코드 변경에 대해 풍부하고 인터랙티브한 설명을 Notion 페이지로 만들어라.

다음 섹션을 이 순서대로 포함해야 한다:

- **ADR(Architecture Decision Record)**: 이 변경이 내린 결정을 ADR 형식으로 기록한다. 다음 항목을 포함한다.
  - **맥락(Context)**: 어떤 문제·제약 때문에 결정이 필요했는가.
  - **결정(Decision)**: 무엇을 하기로 했는가. 한두 문장으로 단정적으로 쓴다.
  - **근거(Rationale)**: 왜 이 결정인가. 검토했던 대안과, 각 대안을 택하지 않은 이유를 함께 쓴다. diff·커밋 메시지·PR 설명에서 근거를 찾을 수 없으면 추측으로 채우지 말고 "근거 미기재"라고 밝힌다.
  - **결과(Consequences)**: 이 결정으로 얻는 것과 감수하는 것(트레이드오프, 새로 생긴 제약).
- **배경(Background)**: ADR을 이해하는 데 필요한 배경 지식만 간략히 설명한다. (주변 코드를 탐색해 파악하되, ADR과 무관한 시스템 설명은 넣지 않는다.) 장난감 데이터(toy data)를 사용한 구체적인 예시와 다이어그램을 활용하라.
- **코드(Code)**: 코드 변경 사항을 높은 수준에서 훑는다. 이해하기 쉬운 방식으로 변경을 묶고 순서를 잡아라. 각 묶음이 ADR의 어느 결정을 구현하는지 연결한다.

형식:

- Notion MCP 도구를 사용해 새 페이지를 만들고, 생성된 페이지의 URL을 반환한다.
- Martin Kleppmann 수준의 명료함과 흐름으로, 고전적 문체(classic style)로 흥미롭게 작성하라. 섹션 간 전환은 매끄럽게 이어져야 한다.
- 다이어그램 팁: 이상적으로는 재사용 가능한 소수의 다이어그램 계열을 골라, 설명 전반의 여러 사례를 그것으로 풀어내는 것이 좋다. 예시 데이터를 반드시 포함하라.
- 핵심 개념이나 정의, 중요한 엣지 케이스 등에는 콜아웃(callout)을 사용하라.
